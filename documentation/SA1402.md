## Cause

A C# code file contains more than one unique type.

## Rule description

A violation of this rule occurs when a C# file contains more than one type. To increase long-term maintainability of the code-base, each type should be placed in its own file, and file names should reflect the name of the type within the file.

It is possible to configure which kind of types this rule should affect. By default, it allows delegates, enums, structs and interfaces to be placed together with a class.

> 📝 For the purposes of this setting, C# 9 records are treated as classes, and C# 10 record structs and C# 15
> unions are treated as structs.

It is also possible to place multiple parts of the same partial type within the same file.

Types with the `file` access modifier are not taken into account.

Top-level statements belong to the implicit `Program` class, which is counted as a class declared before all other
types in the file (and is therefore only taken into account when classes are configured). If the file name matches
another type in the file, the implicit `Program` class is the type that is reported, at the start of the first top-level
statement. A `partial class Program` declaration in the same file is treated as another part of the implicit `Program`
class.

## How to fix violations

To fix an instance of this violation, move each type into its own file.

No code fix is offered for files with top-level statements.

## How to suppress violations

```csharp
[SuppressMessage("StyleCop.CSharp.MaintainabilityRules", "SA1402:FileMayOnlyContainASingleType", Justification = "Reviewed.")]
```

```csharp
#pragma warning disable SA1402 // FileMayOnlyContainASingleType
#pragma warning restore SA1402 // FileMayOnlyContainASingleType
```
